# Maple Forest v4 · 단풍숲 모험

**[지금 플레이하기 · maple-forest-ten.vercel.app](https://maple-forest-ten.vercel.app)**

브라우저에서 플레이하는 Canvas 2D 싱글플레이 액션 RPG입니다. 전사·궁수·마법사로 자유 탐험과 40단계 원정에 도전합니다. 프레임워크나 외부 게임 에셋 없이 HTML/CSS/JavaScript로 실행합니다.

## 실행

`index.html`을 Chrome 또는 Edge에서 열거나 Node.js가 있다면 `npm start`를 실행하세요. 같은 네트워크의 휴대폰에서는 콘솔에 표시되는 8765 포트 주소로 접속합니다. `게임 시작.cmd`, `모바일 실행.cmd`도 사용할 수 있습니다.

## 원정과 성장

- 네 장으로 구성된 40단계 원정, 10·20·30·40단계 보스.
- 다음 경로 선택, 위험과 보상이 큰 정예전, 조건과 비용이 있는 이벤트, 상점·휴식, 전투 보상.
- 처치·생존·호위·보물 방어 목표와 다양한 적 역할.
- 직업별 세 가지 빌드, 유물 효과, 장비의 전투 특성, 장비 비교·장착·판매·분해.
- 원정 기록, 직업별 최고 단계, 장비·유물 도감. 최고 단계 10/20 도달 기록은 보급 경로/시작 유물 선택을 해금합니다.
- 오늘의 원정은 UTC 날짜 시드와 기본 레벨·장비로 시작합니다. 나갈 때 일반 캐릭터를 복원합니다. **기기 내부의 검증되지 않은 개인 도전이며 온라인 경쟁 순위표가 아닙니다.**

일반 원정도 매번 레벨 1·HP 100·MP 60에서 시작합니다. 기존 장비는 사용할 수 있으며, 원정 안에서 얻은 경험치는 나올 때 일반 캐릭터에 한 번만 반영됩니다. 중단 후 재개하면 해당 원정의 성장 상태로 돌아갑니다.

새로 시작하는 원정은 레벨업 시 최대치 증가분(HP 20·MP 8)만 채우고, 전투 회복 보상은 최대 HP 40%·MP 50%를 회복합니다. 물약·휴식·유물은 유지합니다. 직접 전투는 보급을 건너뛰는 대신 진입 시 60골드를 받고, 보급 경로에도 이어질 실제 전투 목표를 표시합니다. 업데이트 전에 진행 중이던 v4 원정은 기존 규칙을 유지합니다.

생존은 초, 호송·수정 방어는 진행률로 표시합니다. 목표가 멈추면 주변 적·거리·높이 중 실제 원인을 안내하고, 보호 대상 HP가 30 이하이면 위험을 표시합니다. 각 목표의 첫 등장 안내와 원정 메뉴에서 대응 방법을 확인할 수 있습니다.

원정 선택과 결과는 저장되어 새로고침으로 보상을 반복 수령하거나 선택지를 다시 뽑지 않도록 구성했습니다. 종료·실패 기록은 최근 100개까지 보관합니다. 새 종료 기록에는 실제 실패 원인과 당시 목표 진행률·대상 HP·남은 시간·내 HP가 함께 남습니다. 상세 정보가 없는 옛 기록의 원인을 추정하지 않습니다.

현재 빌드·이벤트·적·장비의 조건과 확장할 파일은 [콘텐츠 목록과 확장 지점](docs/CONTENT.md)에 정리했습니다.

| Space, W, ↑ | 점프                         |

모바일은 왼손으로 좌우 이동, 오른손으로 점프·스킬·회피·공격을 조작합니다. 이동하면서 공격·점프할 수 있으며, 스킬과 회피 버튼에 남은 시간이 표시됩니다. 세로·가로 화면을 모두 지원합니다.

상단 **메뉴 → 설정 · 저장 파일**에서 효과음·배경음·연출 강도·동작 감소 및 저장 이전을 설정합니다. 메뉴를 열거나 화면을 돌리면 전투가 멈추고 입력이 해제됩니다. 미완료 선택은 **도전**에서 계속하며, **메뉴 → 조작 안내**에서 설명을 다시 볼 수 있습니다.

[모바일 개선 내용·조작·검증 범위](docs/MOBILE-UX.md)를 확인하세요. Chrome 터치 에뮬레이션과 실물 기기 검증을 구분하여 기록했습니다.

## 저장과 기기 이동

자동 저장은 `localStorage`의 `maple-forest-v1` 키를 사용합니다. v1~v3 저장을 v4로 이전하며 기존 성장과 장비를 유지합니다. 이전 원정은 안전한 체크포인트로 이전되므로 옛 전투를 그대로 재현하지는 않습니다.

저장 내보내기로 JSON 파일을 보관한 뒤 다른 기기나 공개 사이트에서 가져오세요. 1MB 이하 JSON만 읽으며 값·장비·원정·기록·설정을 검증합니다. 잘못된 파일은 현재 저장을 덮어쓰지 않습니다. 저장은 브라우저와 주소별로 구분되며 자동 동기화·계정·클라우드 저장은 없습니다. 브라우저 데이터 삭제 전 내보내기를 권장합니다.

오늘의 원정에 들어가기 전 일반 원정을 마무리하거나 중단하세요. 날짜는 UTC 기준이므로 한국에서는 오전 9시에 새 시드로 바뀝니다.

## TypeScript 개발

이벤트 데이터·선택 로직·저장 이벤트 검증을 strict TypeScript로 전환했습니다. 나머지 게임은 기존 JS/Canvas를 유지합니다. 최초 개발 시 `npm ci --include=dev`를 실행하세요. TS 편집 후 `npm run build:typed`로 실행용 JS를 생성합니다. `npm test`, `npm start`, `npm run build`도 먼저 컴파일합니다. 루트의 생성된 이벤트 JS 세 파일은 직접 편집하지 않습니다.

도입 기준, JS·TS 공존 범위와 검증 방식은 [TypeScript 안내](docs/TYPESCRIPT.md)에 정리했습니다. `npm run typecheck`, `npm run test:types`, `npm run check:generated`로 타입 및 생성물 일치를 확인합니다.

## 개발과 검증

```sh
npm test
npm run build
```

`npm run build`는 이벤트 TS를 컴파일한 뒤 번들러 없이 `index.html`이 참조하는 공개 JS/CSS만 `public/`에 복사합니다. 원본 파일은 직접 브라우저에서 실행할 수 있습니다. `npm test`는 전투·원정·저장 테스트를 프로세스 격리 없이 실행합니다.

브라우저 검사에는 별도 개발 도구가 필요합니다. `npm install --no-save playwright`으로 도구를 준비하고 설치된 Google Chrome을 사용하세요(기본 채널 `chrome`). `npm start`를 실행한 상태에서 `npm run test:browser`를 실행합니다. Chrome 대신 번들 Chromium을 쓰려면 `npx playwright install chromium` 실행 후 `BROWSER_CHANNEL=chromium` 환경 변수를 지정하세요. `BASE_URL`(기본 `http://127.0.0.1:8765`), `BROWSER_CHANNEL`, `PLAYWRIGHT_PATH`로 서버 주소·설치 브라우저·모듈 위치를 지정할 수 있습니다.

저장 테스트는 세 이전 버전의 이전, JSON 왕복, 잘못된 가져오기의 기존 저장 보존, 기록 중복 방지, 일일 시드 검증을 포함합니다. 전투·원정·화면 검증 결과는 해당 테스트와 검증 기록을 확인하세요.

이번 원정 업데이트의 `npm test` 51개 검사에는 전체 40단계·저장 137회 왕복을 포함한 **상태 설정 기반 회귀 검사**가 포함됩니다. 별도로 시드 `20260910`과 기본 장비에서 세 직업의 변경 전후 첫 보스까지 총 6회, 변경 후 전사 직접 전투 경로 1회를 **UI·키보드 자동 입력**으로 확인했습니다. 사람의 자연 플레이나 재미 평가는 수행하지 않았습니다. 변경 후 전사 보급 경로에서는 휴식·이벤트 회복을 사용했으나, 골드 축적과 궁수·마법사의 짧은 첫 보스 전투는 남아 있습니다. 세부 수치·실행 조건·미검증 범위는 [원정 선택·회복 규칙과 검증](docs/EXPEDITION-CHOICES.md)을 확인하세요.

기존 **40단계 28분 07.9초·원정 활성 25분 03.6초, 종료 물약 42개**는 이번 변경 **이전**의 전사 출혈 빌드 자동 입력 기록입니다. 이번 규칙으로 전체 원정을 같은 방식으로 다시 측정하지 않았으며, 30~45분 자연 플레이 목표를 입증하지 않습니다. 과거 자료는 [v4 검증 기록](검증.md)에 남겼습니다. 실물 Android/iPhone·Safari와 처음 접하는 플레이어의 목표 이해·보스 예고 대응은 미검증입니다.

공개 배포 절차와 현재 계정 연결 상태는 [배포 안내](docs/DEPLOYMENT.md)에 있습니다.

## 프로젝트 배경

메이플스토리의 횡스크롤 모험과 PokéRogue의 연속 전투·선택 흐름에서 영감을 받았습니다. 공식 프로젝트가 아니며 원작 계정·서버·게임 에셋을 사용하지 않습니다. 그래픽과 사운드는 프로젝트 코드에서 생성합니다.

## 코드 포맷

`npm run format`으로 적용하고 `npm run format:check`로 파일 변경 없이 검사합니다. CI도 같은 범위를 검사합니다. npm에 고정한 Prettier 3.9.6을 사용하며 별도 ESLint/Biome/Git hook은 추가하지 않습니다.

공백 2칸, JS·TS 작은따옴표, 세미콜론 사용, 권장 100자, 후행 쉼표 없음, LF를 적용합니다. JSON·HTML 속성은 해당 형식에 맞는 큰따옴표를 사용합니다. Markdown 문단 줄바꿈과 HTML 공백 의미, 템플릿 안의 문자열은 보존하도록 설정했습니다. EditorConfig와 Git 줄바꿈 규칙도 맞췄으며 Windows 실행용 cmd만 CRLF를 유지합니다. 개인 에디터 설정은 변경하지 않습니다.

루트 게임 소스·설정·문서와 src/types/tests/scripts/docs의 JS·CJS·TS·JSON·CSS·HTML·Markdown, CI YAML이 대상입니다. 의존성·빌드·캐시·외부 라이브러리·압축 파일, npm lockfile, 자동 캡처한 이벤트 기준 JSON, TS에서 생성하는 루트 event-data.js/events.js/event-validation.js는 제외합니다. TS 소스를 포맷한 뒤 `npm run build:typed`로 생성 JS를 갱신해 함께 커밋하세요.

설정 근거: [Prettier 옵션](https://prettier.io/docs/options), [제외 규칙](https://prettier.io/docs/ignore).
