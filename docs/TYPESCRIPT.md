# TypeScript 도입 판단과 1차 전환

기준 코드: `c8f458e`. 이 문서의 판단은 Maple Forest의 실제 공유 상태·저장·정적 배포 구조에 대한 것이며, 파일 수에 따른 보편적 도입 기준이 아닙니다.

## 현황

- 브라우저 런타임 JS 29개, 1,222개 물리 줄, 약149KB. 압축된 한 줄 코드가 많아 줄 수를 복잡도 지표로 사용하지 않았습니다.
- HTML에서 순서대로 로드하는 classic scripts. `window.Game`에 기능과 상태를 추가합니다. 프레임워크와 런타임 패키지 의존성은 없었습니다.
- 기존 npm/Node 환경, 조사 시 Node26.4.0. 빌드는 허용된 HTML/JS/CSS를 `public/`에 복사하고 Vercel이 정적으로 제공합니다.
- 기존 Node 테스트30개, VM 원정/저장 통합 검사와 Chrome 데스크톱·모바일 조작 검사. 기존 TS 설정과 JSDoc 타입 모델은 없었습니다.
- 앱의 외부 JSON 경계는 저장 가져오기/localStorage입니다. 조사한 게임 런타임에는 원격 API 요청·응답 코드가 없습니다. 서버 API용 타입을 임의로 만들지 않았습니다.

## 프로젝트별 도입 기준

반복되는 데이터 계약에 실제 정적 검사 이점이 있고, 해당 영역을 동작 회귀 검사로 보호하며, 현재 배포 형태를 유지할 수 있을 때 단계적으로 도입합니다. 임의 점수나 파일 수 기준은 사용하지 않습니다.

| 항목                                        | 판정 | 근거                                                                                                                                                          |
| ------------------------------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 타입 관련 오류 발생 또는 반복되는 위험 경계 | 충족 | 비용 키를 문자열로 색인하고, 확률 효과의 win/lose 및 nullable 이벤트를 여러 함수에서 해석합니다. 출하 코드의 과거 타입 오류 발생 사실 자체는 확인 불가입니다. |
| 공유 데이터의 일관된 관리 필요              | 충족 | event-data/events/run-validation/stage-ui가 선택·비용·확률·저장 이벤트를 공유합니다.                                                                          |
| 변경 영향 추적의 어려움                     | 충족 | 전역 Game 확장과 스크립트 로딩 순서에 의존합니다. 전체 엔진 전환은 비용이 커 이번에는 이벤트 소비 계약만 명시합니다.                                          |
| 지속 유지보수·협업 이점                     | 충족 | 직업/이벤트/원정 단계 오타, 비용 키 오타, 확률 분기 누락을 컴파일 실패로 바꿀 수 있습니다. 콘텐츠 확장이 계속되는 프로젝트입니다.                             |
| 환경 수용성과 기존 배포 보존                | 충족 | TypeScript7.0.2가 현재 Node에서 동작하고 classic-script JS를 출력하는 것을 확인했습니다. 브라우저 런타임 의존성은 추가하지 않습니다.                          |

**결정: 이벤트 영역부터 TS 도입. 전체 게임의 TS 전환은 이번 범위가 아닙니다.**

원본 이벤트 JS 두 파일을 새 계약과 함께 strict checkJs에 대입하면22개 진단(암시적 any6, 누락 가능6, 문자열 색인5, null 가능4, 산술 피연산자1)이 나왔습니다. 이는 새 검사 기준의 진단이며 실제 플레이 버그22개를 의미하지 않습니다. JSDoc으로도 해결할 수 있지만 같은 공통 계약·분기 타입을 여러 함수에 표현해야 하므로, 이벤트 영역에서는 TS 본문이 더 명확합니다. 기존 단순 렌더링/화면 파일은 JS를 유지합니다.

## 완료한 전환 범위

- `types/events.d.ts`: 이벤트·직업·원정 단계·비용·확률 효과·저장 상태·화면 데이터와 이벤트가 소비하는 Game 계약.
- `src/events/event-data.ts`: 기존12종 이벤트 정의, 타입 검사되는 비용/효과.
- `src/events/events.ts`: 선택·확률 적용·자원 변경·중복 수령 방지·화면 데이터.
- `src/events/event-validation.ts`: 외부 입력을 unknown으로 받고 실제 구조를 검사한 후 반환합니다. 타입 단언으로 통과시키지 않습니다.
- `run-validation.js`: 전체 원정의 재귀 안전 검사는 유지하고 이벤트 필드 검사를 TS 파서에 위임합니다.

strict, noUncheckedIndexedAccess, exactOptionalPropertyTypes 등을 활성화했습니다. any, 무시 지시문, non-null 단언은 사용하지 않습니다. 확률 효과에는 양쪽 결과가 필요하며 확률과 직접 보상이 섞인 모호한 객체는 타입 오류입니다.

공유 타입의 ambient namespace는 기존 classic scripts와 전역 Game 연결을 유지하기 위한 제한된 선택입니다. 전체 엔진의 타입 안전성을 보장하지 않습니다. 새 ESM 로더나 프레임워크, 런타임 검증 라이브러리는 도입하지 않았습니다.

## 저장 호환성과 경계 보완

저장 키 `maple-forest-v1`, 버전4, v1~v3 이전, 정상 저장 구조와 이벤트 결과를 유지합니다. 기존 falsy 유물 값(null/undefined/빈 문자열/0/false)과 이벤트의 추가 필드도 보존합니다.

기존 코드에서 `relic: ['ember']`가 `Object.hasOwn`의 문자열 변환 때문에 저장 가져오기에 통과하는 것을 재현했습니다. 게임이 생성하지 않는 배열·객체 유물 ID는 새 경계에서 거부합니다. 이는 기존 검증의 허점을 보완한 동작 차이이며, 정상 저장의 형식 변경은 아닙니다. TS가 저장값의 진위를 보증하거나 런타임 검증을 대신하는 것은 아닙니다.

## 빌드와 개발

```sh
npm ci --include=dev
npm run typecheck
npm run test:types
npm test
npm run build
npm start
```

TypeScript7.0.2만 직접 개발 의존성으로 고정했습니다. 이 버전의 `module: none`은 지원되지 않아, 실제 출력 검증을 거친 `module: ES2022`와 `moduleDetection: legacy`를 사용합니다. TS 원본은 import/export 없는 IIFE이며 출력은 기존 classic script입니다.

`npm run build:typed`는 `.generated/`에 컴파일한 뒤 루트의 event-data.js/events.js/event-validation.js를 갱신합니다. **루트 세 JS는 실행에 필요한 생성 파일이므로 함께 커밋하며 직접 편집하지 않습니다.** 기존 index.html 직접 열기, Windows 실행 파일, VM 테스트와 브라우저 URL을 유지하기 위한 파일입니다. `.generated/`는 커밋하지 않습니다.

`npm run check:generated`는 컴파일 결과와 커밋된 JS가 일치하는지 검사하며 루트 JS를 덮어쓰지 않습니다. PR CI는 이 검사로 누락된 생성 파일을 차단합니다. npm test/start/build는 컴파일을 먼저 수행합니다. 편집 후 열려 있는 브라우저는 새로고침해야 합니다.

Vercel은 `npm ci --include=dev`로 빌드 도구를 설치한 뒤 기존 `npm run build`와 `public/` 출력을 사용합니다. 공개 게임 실행에는 Node나 사용자의 PC가 필요하지 않습니다. 산출물은33개 공개 파일이며 TS 원본·타입·테스트·중간 출력은 배포하지 않습니다.

## 검증과 남은 범위

- 전환 전30개 테스트·정적 빌드 통과. 전환 후 신규 이벤트·저장 경계 검사를 포함한36개 테스트 통과.
- 전환 전에 고정한294개 이벤트 선택/직업/확률 사례와 비용·보상·중복 수령 결과 비교.
- 유효 타입 사례 통과, 비용 키/직업/이벤트/단계/분기 누락/모호한 효과/미검증 외부 입력/없는 Game 기능 등8개 잘못된 사례의 컴파일 실패 확인.
- 저장의 재귀 검사, 전체 원정 및 이전 저장 테스트를 유지합니다. Chrome에서 데스크톱 시작·빌드 선택·설정·야영지를 확인했고 모바일18개 검사(터치 에뮬레이션, 네 화면 크기, 장비·저장·메뉴·입력)를 통과했습니다. 일부 원정/장비 상태는 강제 설정한 fixture입니다. 실물 모바일/Safari는 별도 검증 대상입니다.

남은27개 기존 런타임 JS(엔진·전투·전체 원정/저장·렌더링·화면 등)는 strict TS 검사 범위 밖입니다. Node 개발 도구와 테스트도 JS입니다. 다음 전환은 장비/빌드 계약 또는 전체 저장 모델을 독립적으로 끝낼 수 있을 때 검토합니다. 이번 단계의 완료 기준은 세 TS 런타임 파일의 실제 사용, strict 통과, 생성물 일치, 기존 저장/이벤트/브라우저 흐름 보존입니다.

공식 참고: [strict 설정](https://www.typescriptlang.org/tsconfig/strict.html), [JS에서 점진적으로 이전하기](https://www.typescriptlang.org/docs/handbook/migrating-from-javascript.html).
