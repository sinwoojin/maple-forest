# 모바일 UI/UX 검증 · 2026-09-10

## 확인한 문제와 변경

| 상황                                          | 영향 / 원인                           | 개선                                                                |
| --------------------------------------------- | ------------------------------------- | ------------------------------------------------------------------- |
| 360×800에서 페이지 높이 1090px                | 조작부까지 스크롤 필요 / 배치         | 동적 화면 높이에 맞는 전투·HUD·조작부 분리                          |
| 844×390에서 페이지 높이 605px, 캐릭터 약 18px | 적과 캐릭터 판독 어려움 / Canvas 축척 | 물리 좌표를 유지하고 모바일 카메라의 표시 범위 조정, 캐릭터 약 33px |
| 동일한 모양의 8개 버튼                        | 오입력 가능 / 크기·배치               | 왼손 좌우 이동, 오른손 2×2 전투 버튼, 보조 버튼 분리                |
| 전투 버튼에 기술/회피 상태 정보 부족          | 실패한 입력 원인 파악 어려움 / 정보   | 남은 시간·마나 부족·물약 수량을 버튼에 표시                         |

좌우 이동 기반 횡스크롤이므로 기존 방향 버튼을 유지했습니다. 조이스틱으로 교체하거나 자동 공격·자동 물약을 추가하지 않았습니다. 기존 누르고 있는 동안의 기본 공격 반복은 유지합니다.

## 조작과 메뉴

- 왼손: 좌우 이동. 오른손: 점프·스킬·회피·공격. 이동과 공격/점프/회피 동시 입력을 지원합니다.
- 세로 주요 버튼은 60~72px, 보조 버튼은 최소 44px입니다. 가로 화면에서는 좌우 조작부 사이에 보조 버튼을 배치합니다.
- 체력·마나·목표는 Canvas 바깥에 표시합니다. 전투 버튼에 스킬과 회피 재사용 시간이 보입니다.
- 상단 **메뉴**에서 직업·가방·기록·설정·조작 안내를 엽니다. 미완료 보상은 **도전** 또는 **원정** 버튼으로 이어갑니다.
- 메뉴·회전·비활성화 시 전투와 목표 시간이 멈추며, 복귀할 때 이전 입력을 해제합니다.
- 메뉴 본문만 스크롤합니다. 닫기/다음 행동은 고정하며 마지막 항목까지 접근할 수 있습니다. 선택지를 스크롤하는 터치 제스처는 선택으로 처리하지 않습니다.
- 가방은 현재 장비 대비 수치와 효과를 표시합니다. 정렬·스크롤을 유지하고 판매/분해의 반환 값을 구분합니다.
- **메뉴 → 설정 · 저장 파일**에서 JSON 내보내기/가져오기를 사용합니다. 저장 키 `maple-forest-v1`, v1~v4 이전 및 저장 구조를 변경하지 않았습니다.
- PC 키보드 조작은 동일합니다. 설정에서 지원 브라우저의 전체화면을 선택할 수 있으며 필수 조건은 아닙니다. 가로 고정도 요구하지 않습니다.

## 재현 명령

```sh
npm start
# 다른 터미널: Playwright와 설치된 Chrome 필요
npm run test:mobile
npm run test:browser
npm test
npm run build
```

`BASE_URL`(기본 http://127.0.0.1:8765), `PLAYWRIGHT_PATH`, `BROWSER_CHANNEL`, `ARTIFACT_DIR`로 환경을 지정합니다. `test:mobile`은 브라우저의 격리된 테스트 저장을 사용합니다.

## 검증 범위

Chrome에서 360×800, 390×844, 844×390 및 1280×900을 확인했습니다. 별도 메뉴 캡처는 768×1024도 포함하여 15종 메뉴 × 5크기, 총 75개입니다.

- CDP 터치 입력: 세 손가락 이동+공격+점프, 회피, 터치 취소, 버튼 밖으로 이동 후 해제, 메뉴 중 입력 해제, 선택지 스크롤 후 선택.
- UI 입력: 새 원정·직업·빌드 선택, 메뉴 복귀, 저장 내보내기·잘못된 가져오기·정상 가져오기·새로고침.
- 상태 준비 후 UI 입력: 가방 장착·판매·분해·정렬, 보상 창 회전·닫기·재열기·한 번 수령. 가방과 보상은 코드로 준비한 테스트 상태입니다.
- 상태 이벤트 주입: `blur` 발생 후 입력 해제·일시정지. 실물 OS 앱 전환이나 화면 잠금 검증은 아닙니다.
- 자연 입력 별도 실행: 세로 화면에서 전사 출혈 빌드로 120.29초, 전투·분기·이벤트·상점·3단계 생존전까지 진행했습니다. UI 클릭/키보드 입력만 사용했고 시간 가속이나 전투 상태 수정은 하지 않았습니다. 사람의 엄지 조작 또는 전체 원정 완료 검증이 아닙니다.
- 추가 확인: 지원 브라우저에서 전체화면 진입/해제, 12종 이벤트의 확률 표시, 긴 메뉴 9개 끝부분, 10회 화면 회전. 상태를 준비한 테스트이며 실물 기기의 회전/노치를 대신하지 않습니다.
- 메뉴 종료 후 OS 키 반복을 모델링한 검사로 남은 키 입력이 재개되지 않음을 확인했습니다. 위험 예고 문구는 화면 가장자리에서도 잘리지 않도록 배치하고, 충돌 뒤 중복 패턴 이름은 숨겨 피해·회복·회피 피드백을 우선합니다.
- 기존 전투·원정·저장 자동 검사 30개 통과. 이번에는 30분 완주 검사를 반복하지 않았으며 콘텐츠·밸런스는 변경하지 않았습니다.

실물 Android/iPhone, Safari, 노치·주소창 변화·화면 잠금·OS 복귀는 미검증입니다. CSS safe-area와 동적 뷰포트 처리는 구현했지만 에뮬레이션을 실기기 검증으로 간주하지 않습니다. 장시간 발열·배터리·저사양 기기 프레임률과 실제 엄지 피로도는 추가 확인이 필요합니다.

## 구현 파일

`mobile.css`: 모바일 배치·공통 버튼·패널·스크롤. `mobile-ui.js`: HUD·버튼 상태·모바일 메뉴/도움말. `mobile-input.js`: 멀티터치·포인터 캡처·입력 해제. `render.js`, `combat-art.js`: 표시 카메라·최대 DPR 2·위험 예고 가독성. `events.js`: 확률 표시용 데이터. `menus.js`, `stage-ui.js`, `archive-ui.js`, `ui.js`, `index.html`: 기존 화면 연결. `tests/mobile-ui.cjs`: 회귀 시나리오.
