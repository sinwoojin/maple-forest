# 원정 선택·회복 규칙과 검증

이번 변경은 기존 원정의 보급 선택과 목표 이해를 연결합니다. 직업·지역·보스·전투 횟수·적 HP를 추가하거나 늘리지 않았습니다. 보급 사용의 필요성이 생긴 사례는 확인했지만, 재미나 전체 경제 균형이 해결되었다고 판단할 자료는 아직 부족합니다.

## 새 원정과 이전 저장

| 항목             | 새 원정 (`rulesVersion: 2`)                                    | 이전 진행 중 v4 원정 (`rulesVersion: 1`) |
| ---------------- | -------------------------------------------------------------- | ---------------------------------------- |
| 레벨업           | 최대 HP +20·MP +8, 현재 값도 증가분만 회복                     | 기존 완전 회복 유지                      |
| 전투의 회복 보상 | 최대 HP 40%·MP 50% 회복, 올림·최대치 제한                      | 기존 완전 회복 유지                      |
| 방어력           | 감산은 원래 피해의 최대 60%, 이후 껍질 유물 ×0.8·반올림·최소 1 | 기존 감산 유지                           |
| 물약·휴식·유물   | 효과·비용·장비 특성 유지                                       | 유지                                     |
| 경로             | 시드 기반 목표·보급, 직접 전투 진입 +60골드(보스 0)            | 기존 순서·진입 보상 유지                 |

예를 들어 원래 피해 16·방어력 31이면 기존 피해 1에서 새 원정 피해 6으로 바뀝니다. 능동 방어·회피의 피해 차단은 유지합니다. 물약은 기본 HP 80(해당 망토 100), 휴식은 HP 60%·MP 완전 회복이며 일괄 축소하지 않았습니다. 상점 가격·물약 수량·유물 슬롯·기존 장비 소유권도 유지합니다.

저장 키 `maple-forest-v1`과 저장 버전 4는 그대로입니다. `rulesVersion`이 없는 기존 v4 저장은 1로 읽습니다. 없는 `nextEncounter`와 `outcome`은 `null`, `seenObjectives`는 빈 배열로 복구합니다. 새 원정은 2로 시작하므로 진행 중 원정의 확정 보상이나 난이도를 소급 변경하지 않습니다. v1~v3 가져오기는 기존 체크포인트 이전 절차를 유지합니다.

새 경로는 다음 실제 전투를 선택지의 `encounter`에 저장하며 보급 선택 후 `nextEncounter`로 유지합니다. 가져오기 검증은 경로 종류·목표·단계의 일관성을 확인합니다. 선택 후 재접속, 보급 이후 전투 진입, 보상 중복 수령 방지와 기존 기록 가져오기를 회귀 검사합니다.

## 경로에서 판단할 내용

- 직접 전투: 준비를 건너뛰는 대신 진입 +60골드. 4의 배수 비보스 단계의 정예전은 치유사의 회복 오라가 있고 완료 시 기존 +90골드·재료 3개도 지급합니다.
- 보급: 이벤트·상점·휴식과 **그 뒤 치를 실제 전투 목표**를 함께 표시합니다. 같은 목표이면 근거 없는 높음/낮음 난이도 차이를 표시하지 않습니다.
- 이벤트·상점·휴식은 시드에 따라 달라집니다. 첫 단계를 제외한 비보스 목적지 세 곳마다 휴식을 선택할 기회를 보장합니다. 보급 선택을 강제하지 않으며 이벤트의 무료 대안, 선택 구매, 무료 휴식을 유지합니다.
- 10·20·30·40단계는 보스입니다. 해금된 추가 보급 경로와 기존 전투 보상도 유지합니다.

확정 경로·보상·이벤트 추첨은 저장 후 다시 뽑지 않습니다. 이전 원정도 표시를 실제 전투에 맞추지만 저장된 선택지와 기존 규칙을 교체하지 않습니다.

## 목표와 종료 이유

생존은 경과·남은 **초**, 호송과 수정 방어는 **진행률**로 표시합니다. 호송·방어는 대상 HP·제한 시간을 함께 보여주며 대상 HP 30 이하에서 `위험`을 표시합니다. 실제 진행 판정과 같은 조건으로 주변 적, 대상과의 거리, 높이 차이 때문에 멈춘 원인을 안내합니다. 메뉴로 일시정지하면 목표 시간도 멈췄음을 표시합니다.

목표 종류별 첫 등장에 짧은 안내를 보여주고 확인 여부를 저장합니다. 원정 메뉴에서도 목표 설명을 다시 읽을 수 있습니다. 새 실패 기록은 보호 대상 체력 소진·목표 시간 초과·실제 공격 원인을 구분하고 당시 단계·진행도·대상 HP·남은 시간·플레이어 HP를 보관합니다. 완료 기록은 마지막 보상을 고른 시점의 상태입니다. 상세 기록이 없는 옛 결과에는 정보가 없다고 표시합니다. 이전 저장의 비정상 공격 이름이 패배 기록을 중단하지 않도록 긴 이름은 100자 안에서 말줄임하고, 문자열이 아니면 상세 원인을 알 수 없다고 기록합니다. 모바일 시작 안내는 키보드 E 대신 원정 버튼을 안내합니다. 긴 기록 제목도 카드 안에서 줄바꿈하며 360·390·844·1280px 화면에서 가로 잘림을 검사합니다.

## 첫 보스까지 자동 입력 비교

기준은 TS·Prettier 선행 변경을 포함한 `f6e6ff4`이고, 변경 후에는 같은 경제·새 경로 구현을 별도 고정 복사본으로 실행했습니다. 이후의 저장 검증·기존 경로 표시 보완과 최종 화면 검사는 별도로 수행했습니다. 이 변경은 선행 TypeScript PR #1을 포함하는 작업 기반에서 작성했으며 선행 PR과의 병합 순서를 보존해야 합니다.

시드 `20260910`, 전사 출혈·궁수 관통·마법사 냉기 빌드, 기본 무기·방어구, HP 100·MP 60·골드 0·물약 5개로 시작했습니다. Chrome headless 1440×1000에서 시드만 시작 전에 고정하고 이후 UI·키보드 입력으로 진행했습니다. HP·단계·시간을 강제로 바꾸거나 가속하지 않았으며 장비를 교체하지 않았습니다. 전투는 기본 공격 유지, 기술 재사용, HP 48% 미만 물약, 주기적 회피, 높이 차이에 따른 점프를 사용합니다.

## 회복·초과 회복 경계 검사

다음은 **상태를 강제로 설정한 단일 효과 검사**입니다. 최대 HP 100·MP 60에서 현재 HP 99·MP 59로 놓고 비교했습니다. 초과 회복은 효과의 명목량에서 실제 증가량을 뺀 값이며 원정 전체의 낭비량을 뜻하지 않습니다.

| 효과                     | 명목량 변경 전 → 후 | 실제 회복 | 초과 회복 변경 전 → 후 | 별도 자원 변화                  |
| ------------------------ | ------------------- | --------- | ---------------------- | ------------------------------- |
| 전투 회복 보상 HP        | 100 → 40            | 1 → 1     | 99 → 39                | 없음                            |
| 전투 회복 보상 MP        | 60 → 30             | 1 → 1     | 59 → 29                | 없음                            |
| 기본 물약 HP             | 80 → 80             | 1 → 1     | 79 → 79                | 물약 −1                         |
| 휴식 HP                  | 60 → 60             | 1 → 1     | 59 → 59                | 회복 선택 사용                  |
| 심장 유물 처치 HP        | 4 → 4               | 1 → 1     | 3 → 3                  | 해당 처치 골드 +14, 회복과 별도 |

샘 유물의 재생은 기본 재생과 합쳐 적용되므로 실제 MP 1을 모두 유물 효과로 귀속하지 않습니다. 레벨업은 최대치 증가 HP 20·MP 8과 기존 결손 회복을 분리하면, 결손 회복만 변경 전 HP 1·MP 1에서 변경 후 0·0입니다. 별도 기준 검사에서 HP 30·MP 10의 레벨업은 기존 120/68에서 새 규칙 50/18이 되며, 같은 상태의 회복 보상은 기존 100/60에서 70/40이 됩니다. 이벤트·유물의 실전 전체 초과 회복량은 전부 계측하지 않았습니다.

## 검증 범위와 재실행

- **상태 설정·VM 검사:** `npm test` 51개 통과. 기존 40단계 완료·저장 137회 왕복, 직업·이벤트·보상·가져오기 회귀와 새 규칙 경계, 4개 시드의 경로 목표·지급, 보급 기회, 재접속 후 목표 고정, 실제 실패 스냅샷·첫 안내 저장을 포함합니다. 40단계 자연 플레이 결과가 아닙니다.
- **UI·키보드 자동 입력:** 위 표의 첫 보스까지 7회. 변경 후에는 보스 보상 선택 후 다음 단계 진입도 확인했습니다. 재미·숙련도·예고 인지의 사람 평가와 구분합니다.
- **브라우저 입력 회귀:** 기존 데스크톱 검사와 Chrome 모바일 에뮬레이션 19개를 실행했습니다. 메뉴·입력 해제·저장 등 시나리오는 `tests/ui-smoke.cjs`, `tests/mobile-ui.cjs`에 있습니다. 상태를 준비한 화면 검사와 실제 터치 입력 검사는 별개입니다.
- **사람의 자연 플레이:** 이번 변경에서 수행하지 않았습니다. 처음 접하는 사람이 선택 이유와 목표 중단 원인을 설명하는지, 첫 보스 예고를 보고 대응하는지는 남은 검증입니다.
- **실물 기기:** Android/iPhone·Safari 미검증입니다. Chrome 화면 크기와 터치 에뮬레이션은 실기기 결과가 아닙니다.

```sh
npm run format:check
npm run typecheck
npm run check:generated
npm run test:types
npm test
npm run build
# 별도 터미널에서 npm start 후, Playwright와 Chrome을 준비하여 실행
npm run test:browser
npm run test:mobile
```

이벤트 TS 생성물을 직접 편집하지 않습니다. 정적 빌드는 공개 스크립트·스타일 36개를 복사합니다. 위 포맷·strict 타입·생성물 일치·타입 계약 검사와 51개 테스트, 정적 빌드, 데스크톱 및 모바일 검사를 최종 코드에서 통과했습니다.

성능은 변경 전 동시 실행에서 저장 호출 p95 약 1.0–1.3ms, 최대 약 13–42ms, 프레임 간격 p95 약 66.7ms였습니다. 메뉴와 세 브라우저 동시 부하를 포함하므로 고립된 성능 벤치마크나 휴대폰 성능으로 일반화하지 않습니다. 저장이 병목이라는 근거를 확보하지 못해 저장 빈도는 바꾸지 않았습니다.

## 남은 한계

각 조건은 단일 시드·1회이며 경로 구성 자체도 달라졌습니다. 전사에서 보급 회복과 직접 전투의 비용 차이를 관찰했지만 통계적 균형이나 난이도 개선을 입증하지 않습니다. 골드가 계속 쌓이고, 변경 후 궁수·마법사의 첫 보스 전투가 각각 3.35·5.22초로 짧아 예고를 읽고 대응할 시간이 충분한지는 추가 관찰이 필요합니다. 이번에는 적 HP나 반복 구간을 늘려 시간을 맞추지 않았습니다.

과거 40단계 자동 입력 약 28분 기록은 이전 규칙의 자료입니다. 이번 규칙의 전체 원정은 VM 진행·결과·저장 회귀만 확인했으며, 후반 실전 회복 경제와 전체 플레이 시간은 다시 측정하지 않았습니다. 다음 검증은 서로 다른 시드·장비의 세 직업 양쪽 경로, 후반 회복·골드 소비, 처음 접하는 플레이어의 목표 이해 순으로 권장합니다. 물약 잔량 자체를 목표로 삼지 않습니다.
